# Mac 유틸리티: 잠자기 방지와 스크롤 반전

이 문서는 이슈 #80–81의 로컬 개발 변경을 설명합니다. 공개 배포나 실제 하드웨어 검증을 뜻하지 않습니다. 두 모듈 모두 플러그인 관리에서 설치한 뒤 사용을 켜야 동작합니다. 생성·설치·설정 화면 진입만으로 assertion이나 이벤트 tap을 시작하지 않습니다.

## 화면 꺼짐 방지

설정 → 설치된 플러그인 → 화면 꺼짐 방지에서 유지 범위와 시간을 고릅니다.

| 옵션 | 동작 |
| --- | --- |
| 화면과 시스템 | `PreventUserIdleDisplaySleep` 요청. 화면 자동 꺼짐과 그에 따른 시스템 idle sleep을 방지합니다. 이미 꺼진 화면을 켜는 명령은 아닙니다. |
| 시스템만 | `PreventUserIdleSystemSleep` 요청. 화면 자동 꺼짐은 허용하고 시스템 idle sleep을 방지합니다. |
| 직접 끌 때까지 | 사용자가 중지하거나 플러그인을 끄거나 앱이 종료될 때 해제합니다. |
| 15분·30분·1시간·2시간 | 선택한 시간 후 해제합니다. macOS assertion에도 같은 timeout과 release 동작을 지정합니다. |

옵션만 저장해도 활성화되지는 않습니다. 실행 중 옵션을 바꾸면 기존 assertion을 해제하고 새 범위·시간으로 시작합니다. 유지 범위·시간과 카탈로그의 사용 선택은 기존 설정과 별도로 보관하며 다른 설정을 덮거나 삭제하지 않습니다. 앱을 새로 실행하면 저장한 시간으로 새 세션을 시작하고, 이전 세션의 남은 시간을 복원하지 않습니다.

메뉴바에는 기존 출퇴근 부엉이와 별도로 작은 상태 부엉이와 **유지 중 / 해제됨 / 실패**가 표시됩니다. 이 행을 클릭하면 플러그인 설정을 엽니다. 팝오버와 설정 화면의 부엉이 버튼은 현재 요청을 중지하거나 다시 시작합니다. 중지·시간 종료 뒤에도 카탈로그의 사용 선택을 유지하므로 다시 시작할 수 있습니다.

- **뜬 눈:** assertion 생성 후 macOS properties의 level이 켜짐으로 읽힌 상태입니다. 실행 중 약 1초마다 확인합니다. 실제 화면이나 하드웨어 절전 상태를 측정한 결과는 아닙니다.
- **감은 눈:** 중지·시간 종료·실패 상태입니다. 실패는 상태 글자와 오류 코드로 구분합니다. 생성 실패나 적용 상태 읽기 실패 뒤에는 사용자가 시작/재시도를 눌러야 새 요청을 만듭니다.
- 시간 종료는 자동 재시작하지 않습니다. 중지·사용 끄기·호스트 종료는 assertion과 타이머를 해제합니다. 시스템 요청은 프로세스 소유이므로 프로세스가 끝나도 유지되지 않습니다.

### 덮개를 닫을 때의 한계

이 플러그인은 **일반적인 덮개 닫힘 동작을 지원한다고 보장하지 않습니다. 이 Mac에서의 실물 결과도 확인하지 않았습니다.** 직접 잠자기, 덮개 닫기, 배터리 부족, 과열에 의한 강제 잠자기를 우회하지 않습니다. 관리자 권한, `pmset` 영구 변경, private API를 사용하지 않습니다.

Apple은 [idle sleep과 forced sleep의 차이](https://developer.apple.com/library/archive/qa/qa1340/_index.html)를 설명하며, IOKit으로 강제 잠자기를 막을 수 없다고 명시합니다. [공식 IOKit 헤더](https://github.com/apple-oss-distributions/IOKitUser/blob/main/pwr_mgt.subproj/IOPMLib.h)는 두 idle assertion의 범위와 Dark Wake에서의 한계를 설명합니다.

외장 화면을 쓰는 덮개 닫힘 모드는 해당 Mac 모델의 Apple 지원 조건을 따라야 합니다. 예를 들어 Apple의 [M3 MacBook Air/Pro 외장 화면 안내](https://support.apple.com/en-la/117373)는 전원과 외장 키보드·마우스/트랙패드를 요구합니다. 이 조건을 모든 Mac 모델이나 주변기기에 일반화하지 않습니다. 실제 지원 여부는 모델·macOS·전원·외장 화면·입력 장치 조건을 기록한 실물 시험이 필요합니다.

## 마우스 스크롤 반전

플러그인 설정에서 손쉬운 사용 권한을 명시적으로 허용한 뒤 사용할 수 있습니다. 자동 승인은 하지 않습니다. 권한 변경과 비활성 tap은 약 3초마다 확인합니다. 권한 철회 때 tap을 해제하며, 복원되면 다시 시작합니다. 생성 실패나 비활성 tap을 활성 상태로 표시하지 않습니다.

| 합성 이벤트 형식 | 세로·가로 동작 |
| --- | --- |
| 라인 기반, gesture phase 없음, momentum phase 없음 | line·point·fixed-point delta를 반전합니다. 타임스탬프와 modifier는 유지합니다. |
| 연속 픽셀 기반 | 변경하지 않습니다. 부드러운 스크롤 마우스도 여기에 포함될 수 있습니다. |
| gesture 또는 momentum phase 있음 | 변경하지 않습니다. |

이 구현은 **물리 마우스와 트랙패드를 식별하지 않습니다.** Apple의 [`scrollWheelEventIsContinuous` 설명](https://developer.apple.com/documentation/coregraphics/cgeventfield/scrollwheeleventiscontinuous)은 픽셀 기반과 라인 기반의 구분입니다. 같은 형식의 부드러운 마우스와 트랙패드 이벤트는 구분할 수 없습니다. 트랙패드를 보호하려고 연속/제스처/관성 이벤트를 그대로 유지하므로 모든 마우스 모델의 반전을 보장하지 않습니다. 장치 드라이버가 트랙패드를 일반 라인 휠로 보내는 경우도 분리할 수 없습니다. 이벤트를 기록하거나 합성 이벤트를 시스템에 게시하지 않습니다.

## 검증 범위

기본 검사 명령은 `swift test --jobs 2`입니다. 작업 환경의 캐시 쓰기 제한이 있으면 `CLANG_MODULE_CACHE_PATH`, `SWIFTPM_MODULECACHE_OVERRIDE`와 SwiftPM의 cache/config/security 경로를 허용된 작업 디렉터리로 지정합니다. `AfterSixChecks`는 별도 실행형 검사이며 Swift test 결과와 구분합니다.

합성 검사는 타이머 경계·재시작·중지·옵션 저장·모드 변경 해제·실패 readback·컨트롤러 해제, 두 축의 delta와 극단값, 연속 입력, 여러 gesture/momentum 단계, 권한 거절/복원/철회와 tap 비활성화를 다룹니다. 네이티브 IOKit assertion 검사는 `HAPPY_LULU_TEST_POWER_ASSERTION=1`일 때만 실행하며 기본 검사에서는 건너뜁니다.

실제 마우스·트랙패드·부드러운 마우스의 두 축과 관성, 실제 권한 철회, 화면 자동 꺼짐, 장시간/잠자기 이후 타이머, 덮개 닫힘과 외장 화면은 별도 하드웨어 수락 검사입니다. 이번 자동 검사는 이 결과를 입증하지 않습니다. 실제 Dev/production 앱 실행과 시스템 설정 변경도 수행하지 않습니다.
