### 사이트 문서 구성과 검증 경계

홈의 컴팩트한 다운로드 흐름은 유지하고 상세 설명을 `/features/`·`/guide/` 한영 문서에서 제공한다. 기능 내비·현재 위치·관련 기능·언어 대응을 함께 갱신한다. 사용자 기능 설명에는 설정 경로/기본값/선택 활성화/Mac 및 macOS26+ 제한을 함께 둔다. 개발용 QA 실행·보고서는 [QA.md](QA.md)에 두며 사용자 플러그인으로 소개하지 않는다.

표시 기준은 **main 구현**과 **공개 다운로드 버전**을 구분한다. 과거 릴리즈 내용을 최신 소스 기능으로 다시 쓰지 않는다. 페이지별로 Mac/Windows·권한/계정·네트워크 조건을 유지한다. 사이트의 현행 코드·반응형 토큰은 실제 `site/dist`를 우선하며 아래 2026-10-21 홈 섹션·테마 수·버전/HTML 개수는 역사 기록이다.

자동 fixture·소스 검사는 실제 데스크톱 클릭/붙여넣기·VoiceOver·잠금해제/재부팅·외부 계정 성공을 뜻하지 않는다. 문서·사이트 작업에서는 관련 정적/링크 검사와 로컬 브라우저 관찰을 따로 기록한다. 이 절을 추가한 사실은 기존 자동 QA를 다시 실행했거나 공개 사이트가 갱신됐다는 증거가 아니다.

## 2026-10-21 상태별 부엉이 로컬 적용 결과 · 34.5

최신 승인 범위는 첨부한 8상태 부엉이 표를 현재 상황에 맞춰 **메뉴바와 패널 좌상단에 함께 표시**하는 것이다. 아래 34.2·34.1 절은 당시 적용 이력이다. 현재 로컬 구현·검증 결과는 이 절을 우선한다. 작업 checkout은 `app/happylulu/design-refresh-local`, branch `cy-agent/design-refresh-local`, 기준 HEAD `8a4a5380f4fd8b55848cd2e5357296dbdcc35a5c`이며 변경은 해당 checkout의 로컬 미커밋 상태로 유지한다.

- **있는 기능:** 출근 입력·5개 근무유형·계산·기록·설정·6개 테마·개인 아이콘 설정을 유지한다. 상태 우선순위는 연차/공가 → 오늘 쉬는 날 → 출근 기록 없음 → 예정 퇴근 시각 경과 → 근무유형이다. 이 디자인 변경은 계산·상태 판정·사용자 데이터 저장 계약을 바꾸지 않는다.
- **뺀 기능/요소:** 기능 제거 없음. 근무유형 옆 부엉이 장식 제거를 유지하고, 일반근무·룰루데이·오전반차·오후반차·연차/공가의 캡슐 아래 중복 설명줄을 제거한다. 출근 대기·예정 퇴근 시각 경과·오늘 쉬는 날은 추가 상태 설명을 유지한다.
- **추가/변경:** 메뉴바는 26×18 pt 단색 template 눈·부리 8종, 패널의 `HappyLulu` 왼쪽은 같은 상태의 28×28 pt 컬러 얼굴 PNG 8종을 사용한다. 오전 반차는 보는 사람 기준 왼쪽 눈, 오후 반차는 오른쪽 눈을 감는다. 룰루데이는 양쪽 눈웃음과 열린 부리, 예정 시각 경과는 눈웃음과 닫힌 부리로 구분한다. 문자와 접근성 이름도 상태에 연결한다.
- **Dock·설정:** 선택한 전체 올루루+시계 PNG를 기본 앱/Dock 아이콘으로 적용한 로컬 build 34.3 설치 이력을 반영한다. `Resources/HappyLuluIcon.png`와 `Resources/HappyLuluBrand.png`는 선택 원본과 동일한 SHA256 `82a8ba2d30478b3a68a25a9b74071c4d01706263734494e2e8a40a26a55fa084`다. 설정 사이드바는 24×24 pt 정적 브랜드 그림이며 상태별 얼굴과 구분한다. 기존 사용자 아이콘 선택·개인화 경로를 유지한다. 사이트 자산 교체는 별도 대기다.
- **원본·제작:** [첨부 원본과 8종 자산·제작 기록](../../../../디자인/happylulu/2026-10-21-design-update/state-assets/README.md)을 보존한다. 컬러 얼굴은 첨부 표를 참조해 built-in imagegen으로 재구성한 투명 PNG이며 원본 픽셀을 그대로 잘라낸 결과가 아니다. 메뉴바는 코드 벡터로 재구성한다. 런타임 PNG는 `Resources/OwlStates/`에 포함한다.

- **설치·보존:** arm64 release 빌드와 기존 고정 인증서 서명을 확인한 1.5.18 / 로컬 build 34.5 / `2026-10-21-state-icons`를 `~/Applications/HappyLulu.app`에 설치·재실행했다. 후보/설치 번들 일치·엄격한 서명·단일 프로세스 PID 26953을 확인했다. 재실행 후 출근/플러그인·외관 전체·일반 설정·캘린더 DB/WAL 보존 대조는 모두 참이다. 복구본 `~/Applications/.HappyLulu-backups/20261021-173213`을 보존했고 로컬 번들의 자동 업데이트 서비스는 비활성이다.

## 2026-10-21 헤더 후속 로컬 적용 이력 · 34.2

사용자의 후속 승인에 따라 패널·설정의 좌상단에 선택 HappyLulu 캐릭터 PNG를 적용하고 근무유형 옆 40 pt 부엉이 장식을 제거했다. 이 절은 34.2 당시 결과이며 최신 추가 변경은 상단 34.5 결과 절을 따른다.

### 1.2 권장 방향과 비기능 확장 경계

1차 권장 방향은 **정돈된 민트 기본면, 라벤더 올루루 보조 강조, 큰 시각 숫자, 짧고 분명한 상태 문구**였다. 이 기록은 보존하되 2026-10-21 2차 사용자 피드백에 따라 민트를 기본면으로 고정하는 제안을 재검토한다. 최신 후보는 3.2의 A 오프화이트·보라와 B 크림·보라·소량 앰버이며 추천은 A다. 두 후보는 원본에서 추출한 색상값이 아니다. 현행 컴팩트 패널·통합 설정·기존 5개 테마와 개인화를 보존한다. 이후 사용자가 A안을 승인했으며 Mac 로컬 적용 범위는 문서 상단을 따른다.

Mac은 현재 시스템 글꼴을 유지하는 방향을 권한다. 웹에는 기존 브랜드 문서의 Pretendard 규칙을 적용 후보로 둔다. 실제 폰트 등록·CSS·앱 글꼴 변경은 이 명세 작업에서 하지 않는다. 재택근무 유형·휴가 신청·클라우드 계정·신규 대시보드·플러그인 마켓을 시안에 추가하지 않는다. Windows는 현재 트레이·진행 막대·설정 탭을 보존하며 Mac 화면을 Windows 지원처럼 제시하지 않는다.

### 1.4 아이콘 제작 기하

[ICON-GEOMETRY.md](../../../../디자인/올루루/앱-브랜딩-제안/ICON-GEOMETRY.md)의 현행 측정과 향후 제작 규격을 구분한다. 선택 PNG 1254×1254의 불투명 타일 폭 1122/높이 1095, 좌/상/우/하 여백 65/81/67/78 px다. 불규칙 곡률이므로 현행 PNG에 정확한 단일 R 값을 붙이지 않는다.

향후 공통 제작 템플릿은 1024 캔버스, 타일 x64/y64/896×896/R200, 캐릭터 x128/y128/768×768, 배지 x704/y704/224×224/R56, 외부 그림자 없음이다. 이는 **아직 적용되지 않은 제작 규격**이다. 기존 PNG를 리사이즈했다고 정규화 완료로 기록하지 않는다. 원본 레이어·같은 마스크·템플릿 재사용이 필요하며 실제 교체는 별도 결정이다.

### 2.4 원본 기반 눈과 상태 표정: 2차 피드백

HL-ADD-002/003의 34.1/34.2 로컬 적용은 이력이다. 최신 첨부 8상태 표에 따른 **34.5 메뉴바·컬러 헤더 동기화는 로컬 구현·검증·설치 완료**이다. 이번 후속 범위는 색감, 눈 원형과 표정 정교화다. 첨부 표와 재구성 PNG의 출처는 HL-ASSET-005에 둔다. [원본 캐릭터 PNG](../../../../디자인/올루루/assets/올루루-기본.png)를 정답 마스터로 삼으며, 기준 마스터를 추출·정면 재구성하는 작업과 원본 중첩 비교가 필요하다. [기쁨](../../../../디자인/올루루/emotions/올루루-기쁨.png)·[집중](../../../../디자인/올루루/emotions/올루루-집중.png)은 표정 참조다. 형태 마스터는 하나로 유지하며 앱+시계 합성 PNG를 눈 형태 마스터로 쓰지 않는다. 문서·새 벡터 시안이 있다는 사실을 직접 추출·tracing 완료 증거로 쓰지 않는다.

기존 v3의 대칭 테두리, 동일한 수직 동공과 물방울 부리는 원형과 차이가 있다. 원형의 핵심은 **깊은 V자 형태의 크림 연속면, 크고 기울어진 동공, 작은 주황 부리**다. 원본과 비교할 때 눈 주변 면이 분리된 테두리처럼 바뀌지 않는지, 동공의 크기·기울기·시선과 부리의 위치·비례가 유지되는지 확인한다. v3 원본은 이력으로 보존하며 그대로 최종 적용할 대상으로 확정하지 않는다.

상태는 두 축을 사용한다. 첫 축은 기존 근무 유형인 일반·오전 반차·오후 반차·룰루데이·연차/공가다. 둘째 축은 기존 기록과 계산 결과인 출근 기록 없음·예정 퇴근 시각 전·예정 퇴근 시각 경과다. 오늘 쉬는 날은 기존의 별도 억제 상태로 우선 판정한다. 새 표정 때문에 계산·기록·상태 전이를 만들거나 변경하지 않는다.

표시 우선순위는 **연차/공가 → 오늘 쉬는 날 → 출근 기록 없음 → 예정 퇴근 시각 경과 → 근무 유형**이다. 상위 상태가 해당하면 하위 상태를 대표 표정으로 겹쳐 표시하지 않는다. 아래 8개를 최신 첨부 표에 맞춰 메뉴바 벡터·컬러 헤더 PNG에 대응한다. 픽셀 원본 추출이 아닌 재구성이다. 34.5의 fixture 검증·로컬 설치는 확인했으며 실제 데스크톱의 추가 사용 평가는 남아 있다.

| --- | --- | --- |

26×18 pt 단색 메뉴바와 28×28 pt 컬러 헤더를 1×/2×, 밝고 어두운 배경에서 원형 식별과 8개 상태의 구분성을 검증해야 한다. 색이나 윙크 방향만으로 상태를 전달하지 않으며 문자·접근성 설명을 함께 사용한다. 단색 메뉴바에서도 의미가 남아야 한다. 이전 34.1/34.2 fixture 검사는 해당 당시 자산의 이력이며, 최신 34.5 자산의 한영 기본/펼침 패널·밝고 어두운 1×/2× 렌더, 경계·빈 알파·명암 검사를 통과했다. 실제 메뉴 클릭·VoiceOver 검증은 남아 있다. 웹에서는 브랜드 표현·가상 시연 상태에만 사용하며 방문자의 실제 근무 상태를 읽거나 표시하는 것처럼 표현하지 않는다.

### 3.2 브랜드 참조와 권장 역할

[브랜딩 갤러리](../../../../디자인/올루루/앱-브랜딩-제안/proposal.html)의 CSS는 ink `#352C49`, muted `#70667D`, purple `#7150A0`, line `#E5DDEB`, paper `#FFFDF9`, 배경 `#F7F3EC`를 사용한다. 카드 R26/목업 R22/모바일 목업 R14는 **갤러리 표현값**이며 앱 공식 토큰이 아니다.

1차 권장안은 현행 앱 소프트 민트 기본면과 라벤더 보조 강조였다. 이 이력은 보존하되 2026-10-21 2차 사용자 피드백으로 색감 제안을 다시 검토한다. 아래 두 후보 중 **A가 승인되어 Mac 로컬 적용됐다**. B는 비교 이력이다. HEX는 시안을 위한 후보이며 원본 PNG에서 추출한 색상값이 아니다. 기존 5개 테마와 개인화 기능은 그대로 보존한다.

| 색감 후보 | 면·본문·강조 | 적용 판단 |

[후보 색상 대비 계산](../../../../디자인/happylulu/2026-10-21-design-update/revision-2/palette-contrast.json)은 sRGB 색상쌍의 정적 계산이다. A의 본문/오프화이트는 13.05:1, 흰 버튼 글자/보라는 5.82:1, 보라 선택 글자/라일락은 4.86:1이다. B의 본문/크림은 12.53:1, 흰 버튼 글자/보라는 5.60:1이다. 앰버/흰색은 2.00:1이므로 작은 글자에 쓰지 않고 장식으로 한정한다. 이 계산은 실제 UI·메뉴바 소형 표현·접근성 전체의 통과 증거가 아니다.

두 후보 모두 실제 화면에서 본문·포커스·오류 대비를 확인해야 한다. 브랜드 그림의 크림색·라벤더·주황을 버튼·오류·선택 상태에 무조건 적용하지 않는다. 후보 선택이 기존 테마 저장값이나 사용자 색상을 덮어쓸 근거가 되지 않는다.

### 3.4 접근성 수용 기준

- 색 외에 텍스트/형태/선택 표시로 상태를 구분한다. 대비 낮음 경고·입력 오류·비활성·stale 결과에 읽을 수 있는 설명을 둔다.
- 키보드 Tab/Shift+Tab 순서와 visible focus가 화면 순서에 맞는다. Enter/Escape는 편집 저장/취소 계약에 맞고 메뉴 Escape는 닫힘과 포커스 복귀를 유지한다.
- 메뉴바·설정·유형·아이콘 선택·캘린더 날짜·새로고침·CAPTCHA 등 아이콘만 있는 컨트롤에 의미 있는 접근성 이름을 둔다. 시각/유형/일정의 읽기 순서를 확인한다.
- 스크린리더가 기록 없음/연차/휴무/권한 없음/오류를 다른 상태로 읽는다. 긴 제목 생략 시 전체 내용 접근 경로를 유지한다.
- native 28 pt 설정 버튼·27 pt 캡슐은 현행 치수다. 확대 클릭 영역·키보드 접근으로 실제 사용성을 검증하며 현행 치수 자체를 접근성 통과 증거로 쓰지 않는다.
- 애니메이션은 장식이며 reduced motion에서 기능을 잃지 않는다. 초 단위 갱신이 매번 스크린리더 공지를 발생시키거나 포커스를 이동시키지 않는지 확인한다.
- 한영·다크/라이트·5개 테마·개인 색상·Retina 1×/2×·최소 창/모바일에서 잘림과 겹침을 확인한다. 확대/긴 문구가 실패하면 정보/기능 삭제 대신 레이아웃으로 해결한다.

## 5. 적용·검증·변경 관리

### 5.1 명세와 제안서의 표기 규칙

모든 제안 화면은 기능 ID, 원본/선택/제안 상태, 가상 데이터 여부와 대상 플랫폼을 적는다. 앱과 사이트 제안서는 분리한다. 앱 제안의 설정·숫자·캘린더는 앱 치수로, 사이트 제안은 웹 반응형 치수로 관리한다. 앱 시안이 실제 제품 스크린샷처럼 보이면 `소스 기반 재구성`을 붙인다.

선택된 브랜드 PNG와 메뉴바 심볼 이력은 함께 보여줄 수 있으나 제품 적용 상태를 각각 적는다. 2026-10-19 v3 선택 방향은 이력으로 보존하고 2026-10-21 2차 피드백으로 재검토한다. 원본 PNG를 정답 마스터로 삼아 눈 원형·표정을 정교화하며 v3 그대로 적용을 확정하지 않는다. runtime 앱 PNG는 HL-DEC-003의 후속 승인으로 34.3에 교체·로컬 설치했다. 사이트 PNG 적용은 대기다. 새 시안에서 [기능 명세의 제거 이력](FEATURE-SPEC.md)을 지우지 않는다. 진행 막대 복원, 탐색 단축, 사이트 아이콘 교체와 웹 폰트·토큰 적용은 결정 필요 항목으로 남긴다.

### 5.3 문서 유지와 남은 결정

기능 변경은 기존 ID를 유지하고 기능·UI·수용 검사를 함께 갱신한다. 제거 시 사유, 승인 근거, 날짜·커밋, 대체, 데이터 영향을 제거 원장에 남기며 행을 삭제하지 않는다. 사이트 주소·앵커도 호환성 결정 없이 제거하지 않는다. 공통 브랜드 원본은 루트 `디자인/`, 실제 제품 자산은 제품 저장소에 두며 양쪽 적용 상태를 따로 기록한다.
