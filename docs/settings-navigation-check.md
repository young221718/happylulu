# 설정 내비게이션 회귀 검사

2026-10-19, Mac 1.5.17 build33의 `c44cdb8`을 기준으로 외관 화면 진입과 사이드바 클릭 영역을 비교했습니다.

## 원인과 수정

외관 화면의 SwiftUI label이 다시 계산될 때마다 기본 아이콘 네 개를 TIFF로 변환하고 새로운 `CIContext`에서 틴트를 렌더링했습니다. 이 작업이 메인 스레드에서 반복되었습니다. 모델별로 렌더링된 기본 아이콘을 보관하고, 첫 요청에서 생성한 context를 재사용합니다. 원본 해상도와 색상 처리 방식은 유지합니다. 사용자 이미지 로딩은 캐시에 넣지 않아 가져오기·교체·저장 실패 처리를 유지합니다.

사이드바는 full-width frame과 padding이 있었지만 plain Button의 투명 영역에 클릭 모양이 없었습니다. 공통 label에 `contentShape(Rectangle())`를 적용해 기본 설정과 설치된 플러그인 행 전체에서 같은 버튼 동작을 실행합니다.

## 재현과 검사

```sh
bash scripts/check-settings-navigation.sh
```

검사에는 macOS 그래픽 세션이 필요합니다. 오래된 `check-appearance-model.sh`는 별도 앱 번들을 만들므로 고정 Dev 앱 식별자만 허용하는 로컬 환경에서는 실행하지 않습니다. 그래픽 접근이 제한된 sandbox에서 Core Image fallback을 성능 개선으로 해석하지 않습니다.

내비게이션 검사는 앱 번들을 등록하지 않는 별도 프로세스에서 실제 `SettingsView`를 `NSHostingView`에 호스팅합니다. 임시 출근 기록·외관·플러그인 저장소만 사용하며 캘린더 런타임, 로그인 변경, 업데이트 시작을 비활성화합니다. 목록 행의 프로그램 선택 연결, 8개 테마의 사이드바·일반 4행·외관 영역 배치, 최소 폭에서의 한국어 행을 비교합니다. 합성 AI 사용량 플러그인에서 스위치 위치, 사용 상태 변경과 재생성 후 보존도 검사합니다. 창 액세서리가 세 버튼과 겹치지 않고 입력을 통과시키는지도 확인합니다. 합성 프로세스는 key window가 아니므로 실제 마우스·키보드·창 드래그 통합 검사를 대신하지 않습니다.

`HAPPY_LULU_NAVIGATION_EVIDENCE=/absolute/output/path`를 지정하면 합성 화면 PNG를 보관합니다. 현재 fixture는 최신 일반 설정 행의 geometry 계측 지점을 사용하므로 아래 과거 버전 비교에는 당시 버전의 검사 스크립트가 필요합니다. 작업 트리를 되돌릴 필요는 없습니다.

2026-11-14 메뉴 통합 검사는 기본 네 메뉴와 합성 설치 플러그인 두 개로 총 여섯 행을 기대합니다. 일반 하단 업데이트, 근무 하단 출근 기록, 화면/플러그인 제목과 한국어 제목을 확인합니다. 기존 목적지의 사이드바 선택과 직접 스크롤, 위로 스크롤한 후 같은 목적지의 반복 진입, 스크롤 중 제목의 고정도 검사합니다. `HAPPY_LULU_MATERIAL_MODE=legacy`로 대체 재질도 확인할 수 있으나 구형 macOS 실기 검사를 대신하지 않습니다.

같은 날 디테일 개선 검사에는 일반·업데이트의 값/스위치가 같은 오른쪽 끝에 정렬되고 자기 행을 벗어나지 않는지 확인하는 계측을 추가했습니다. 8개 테마의 영어와 최소 창의 한국어, 근무·휴게 조작을 포함하며 `updates-korean.png`·`work-korean.png`도 저장합니다. 글자의 시각적 무게, 펼친 안내의 실사용과 VoiceOver 이름·값은 이 geometry 검사만으로 보장하지 않습니다.

`HAPPY_LULU_EXPANDED_HELP=1`은 임시 검사 소스에서 세 안내를 펼친 상태로 렌더하여 한영 긴 문구의 배치를 확인합니다. 실제 앱의 저장값이나 기본 접힘 상태는 바꾸지 않습니다. 펼침/접힘 조작과 목록 포커스에 따른 선택 대비는 실제 고정 Dev에서 별도로 확인합니다.

| 클릭 검사 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| 텍스트·아이콘 영역 | 8/8 | 8/8 |
| 가로 여백·빈 공간·세로 여백 | 0/20 | 20/20 |

외관 모델 검사는 반복 요청의 이미지 재사용, 팔레트/HEX 편집 후 재사용, 다른 원본을 가진 모델 간 분리, 다섯 이미지의 구분, 사용자 이미지 교체, 저장 실패/재시작/손상 파일 보존을 검증합니다.

## 로컬 측정

macOS 27.0.1 arm64, Swift 6.4, 같은 900×700 화면과 저장소 PNG(1254×1254), 같은 컴파일 설정에서 비교했습니다. 내비게이션 변경 직전부터 run loop 처리와 CPU bitmap 생성 완료까지 monotonic clock으로 측정합니다. 아이콘 선택 영역은 최초 viewport 아래에 있지만 실제 SwiftUI 구성 경로에서 렌더링됩니다. 최초 진입은 각 프로세스의 한 번, 재진입은 5회, 팔레트 변경은 다섯 팔레트 각각 한 번입니다.

| 측정 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| 최초 외관 진입 | 436.72 ms | 143.87 ms |
| 외관 재진입 중앙값 (5회) | 378.14 ms | 51.25 ms |
| 팔레트 변경 중앙값 (5회) | 183.43 ms | 43.19 ms |

별도 `swiftc -O` 모델 프로브에서 패키징된 ICNS의 네 틴트 요청을 5개 새 프로세스에서 비교했습니다. 프로세스별 첫 요청 합계 중앙값은 132.329→61.537 ms, 이후 5회씩 총25회 합계 중앙값은 116.525→0.017 ms였습니다. 이 수치는 뷰 전체 시간과 별개이며 운영체제/GPU 캐시까지 초기화한 측정은 아닙니다.

성능 수치는 설명용이며 CI 통과 임계값으로 쓰지 않습니다. CI에서는 동작·캐시 회귀 검사를 실행합니다. CLI 호스팅은 이 호스트에서 SwiftUI 접근성 자식을 노출하지 않아 AX/키보드 검증을 대신하지 못합니다. 실제 모니터의 표시 완료, 사용자의 설치 환경, Intel 성능과 배포 수락은 별도입니다.

## 2026-11-14 Mac 유틸리티 후속

일반의 업데이트 자동 확인·설치 토글을 제거해 정렬 기준은 현재 버전 행만 포함한다. `check-panel-focus.sh`는 별도 앱 없이 비등록 CLI로 실행하고, 설정·종료 독립 28pt 클릭 영역과 편집 중 종료의 동기 저장/무효 입력 차단/ESC 취소를 검사한다. `MacUtilitiesIntegration`을 사용하는 수동 컴파일 검사에는 해당 타깃의 object를 함께 링크한다. [설계·검증 결과](../design/plugins/2026-11-14-mac-utilities.md)
