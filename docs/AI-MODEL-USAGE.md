# AI 모델 사용량 플러그인

로컬 개발 후보에서는 설정 → 플러그인 관리에서 **AI 사용량**을 설치한 뒤, 설치된 플러그인 → AI 사용량의 **사용량 보기**를 켭니다. 처음 설치하면 사용은 꺼져 있으며 기존에 저장한 활성화 선택은 유지합니다. 플러그인을 꺼도 설치와 설정이 보존되어 같은 화면에서 다시 켤 수 있습니다.

계정 목록에서 Codex·Antigravity 연결을 선택하면 메뉴바에 `Codex 72%`처럼 주간 잔여 한도를 표시합니다. 유효한 속도 측정값이 있으면 메뉴바에도 `tok/s`를 함께 표시합니다. 선택한 연결 하나만 갱신하고 표시합니다. 상세 설정은 사이드바의 **AI 사용량**이나 활성화된 메뉴 패널의 사용량 행에서 엽니다.

- 주간 잔여량, 초기화 시각, 사용량의 기준 시각
- 최근 최대 1시간의 관측값으로 계산한 시간당 소모율
- 자동 갱신 1·5·10·15·30분, 기본 5분과 수동 새로고침
- 메뉴바 표시: 기본 `제공자 이름 + %`, 아이콘 + %, 또는 `%만`
- 잔여량 부족 알림
- Codex 최근 로컬 세션 자동 관측과 제공자별 추가 연결로 확인하는 평균 출력 속도(`tok/s`)

표시 및 갱신 설정은 왼쪽 항목명, 가운데 현재 표시 미리보기, 오른쪽 선택으로 구성됩니다. 표시 방식·갱신 주기·알림 기준은 모든 연결이 공유합니다. Codex 아이콘은 공식 윤곽 심볼을 투명 배경의 16pt 단색 이미지로 표시합니다. 입체 앱 아이콘의 배경·그림자를 축소하지 않으며 밝은 화면·어두운 화면·메뉴바 선택 상태에 맞춰 색을 적용합니다. 심볼은 앱에 포함되어 Codex GUI 앱 설치에 의존하지 않습니다. Codex 이미지 생성에 실패하거나 다른 제공자를 선택하면 아이콘 선택은 보존하고 제공자 이름을 표시합니다.

주간 잔여량과 시간당 소모율은 주간 한도의 비율입니다. 모델별 토큰 수·요청 수·API 비용을 의미하지 않습니다. 시간당 소모율은 최소 1분 간격의 관측 두 개가 필요하며, 데이터 부족은 `—`로 표시합니다. 분당 소모율은 표시하지 않습니다. 선택형 토큰 속도 측정은 이 비율과 별개의 지표입니다.

## 계정과 연결

**계정 추가**에서 제공자를 고른 뒤 이름을 정합니다. **연결** 목록으로 전환하고 **목록에서 제거**로 등록을 해제할 수 있습니다. 마지막 연결은 제거할 수 없습니다. 연결을 바꾸면 진행 중인 조회·로그인 대기를 중단하며 이전 연결의 늦은 응답을 표시하지 않습니다. Codex는 연결별 관측 기록과 알림 중복 방지 상태를 따로 보관합니다. 목록에서 제거해도 CLI 로그인 파일이나 계정 폴더를 삭제하지 않습니다.

지원하지 않는 이전 개발 연결은 설정을 보존한 채 조회·로그인·토큰 측정을 중지합니다. Codex 또는 Antigravity 연결을 선택하거나 새로 추가해 사용합니다.

기존 단일 Codex 설정은 기본 Codex 연결로 읽으며 실행 파일 경로·표시 설정·최근 관측 기록을 유지합니다. 새 연결을 추가하는 것만으로 외부 도구에 계정이 생성되거나 로그인되지는 않습니다.

### Codex

기본 연결은 기존 Codex CLI 로그인을 사용합니다. 하단 **Codex 연결**에서 실행 파일을 선택하거나 **자동 찾기**로 되돌릴 수 있습니다. **ChatGPT로 로그인**은 선택한 연결의 계정을 바꾸며 API 키 로그인에는 ChatGPT 주간 한도가 없습니다.

업무·개인 계정을 나누려면 각 연결에 서로 다른 절대 경로의 **계정 폴더**를 지정하고 **계정 폴더 적용** 후 로그인합니다. 조회와 로그인에 같은 `CODEX_HOME`을 사용합니다. 폴더를 비워 두면 기존 CLI 환경과 기본 로그인을 사용하므로, 이 상태에서 다른 계정으로 로그인하면 기존 Codex CLI 계정도 변경됩니다.

### Antigravity

기본은 직접 내보낸 `/usage` JSON 보고서를 읽는 방식입니다. 선택한 연결에서 **Antigravity CLI로 자동 조회**를 켜면 매 갱신마다 CLI 버전을 확인하고 `agy -p "/usage" --output-format json`을 실행합니다. **1.1.11 이상의 정식 버전**이 필요하며 실행 파일을 자동으로 찾지 못하면 직접 선택할 수 있습니다. 구버전은 `/usage`를 일반 프롬프트로 처리할 수 있어 자동 실행하지 않습니다.

자동 조회를 켜면 사용자의 CLI 설정에 따라 MCP 서버·훅·확장도 실행될 수 있습니다. 조회 취소·종료 시 실행한 프로세스 그룹을 정리하지만 별도 프로세스로 분리된 자식은 남을 수 있습니다. 이 제한을 확인한 경우에만 자동 조회를 켜세요. HappyLulu는 프로젝트 설정을 피하도록 임시 작업 폴더에서 실행하고 자동 업데이트·브라우저 실행을 억제하지만 사용자 CLI 설정 전체를 차단하지는 않습니다.

자동 조회를 끄거나 CLI 조회가 실패하면 선택한 JSON 파일을 읽습니다. 터미널에서 로그인한 뒤 다음과 같이 파일을 만들 수 있습니다.

```sh
agy --version
agy -p "/usage" --output-format json > /tmp/antigravity-usage.json
```

HappyLulu의 **JSON 파일 선택**으로 보고서를 고르거나 절대 파일 경로를 입력하고 **파일 경로 적용**을 누릅니다. 파일 읽기 모드의 **지금 새로고침**은 기존 파일만 다시 읽으므로 사용자가 새 보고서를 직접 만들어야 합니다. 이 모드에서는 HappyLulu가 Antigravity CLI·MCP·확장을 실행하거나 로그인 상태를 바꾸지 않습니다.

위 명령을 터미널에서 직접 실행하면 사용자의 Antigravity CLI 설정에 따라 MCP나 확장이 실행될 수 있습니다. 실행 전에 해당 CLI 설정을 확인하세요.

현재는 보고의 **Gemini 주간 한도**만 표시합니다. 주간 한도가 없거나 응답 형식이 맞지 않으면 값을 추정하지 않습니다. 다른 모델 한도와 5시간 한도를 Gemini 주간 한도로 바꾸어 표시하지 않습니다.

1 MiB 이하의 일반 JSON 파일만 읽으며 심볼릭 링크는 거절합니다. 파일의 수정 시각이 미래이거나 15분보다 오래되었거나 주간 초기화 시각이 지났으면 값을 표시하지 않습니다. 화면의 기준 시각은 **파일 수정 시각**이며 서비스에서 실제로 조회한 시각을 증명하지 않습니다. 오래된 보고서를 복사하거나 수정 시각만 바꾸어 최신 값으로 사용하지 마세요.

Antigravity 연결은 현재 CLI 로그인 또는 선택한 보고서 하나를 사용합니다. 계정 추가를 다시 눌러도 기존 Antigravity 연결을 선택합니다. CLI 응답과 파일 보고서 모두 계정 신원을 확인할 수 없어 다중 계정 분리·관측 이력·시간당 소모율·잔여량 알림은 제공하지 않습니다.

**사용량 보기**를 끄면 타이머·로그인 대기·진행 중인 사용량 조회를 중단하고 표시를 제거합니다. 설정과 최근 관측 기록은 보존합니다. Codex의 일시적인 조회 실패는 마지막 값을 이전 조회 값으로 표시합니다. 로그아웃·한도 미제공 상태, Antigravity 보고서 오류는 미확인 값으로 표시합니다. 초기화 이후 잔여량을 임의로 100%로 만들지 않습니다.

비밀번호와 서비스 인증 토큰은 플러그인이 직접 저장하지 않습니다. Codex는 CLI가 인증을 관리합니다. Antigravity는 선택한 JSON 파일을 읽거나 사용자가 자동 조회를 켰을 때 CLI를 실행합니다. 사용량 조회용 명령은 모델 추론을 요청하지 않지만 Antigravity CLI의 MCP·훅·확장 실행 제한은 위와 같습니다. 계정 식별값을 얻은 한도 연결은 식별값을 해시로 보관하고 최근 2시간의 한도 관측만 로컬에 저장합니다. 계정·초기화 주기 변경, 긴 공백, 서버 보정은 분석 구간을 나눕니다. Codex의 기준 시각은 조회 완료 시각, Antigravity는 CLI 조회 완료 시각 또는 보고서 파일 수정 시각입니다.

## 토큰 속도 측정

**사용량 보기**를 켜고 Codex 연결을 선택하면 **최근 30일 생성 세션 자동 관측**이 기본 출처로 시작됩니다. 새 CLI 실행 명령이나 주간 한도 값 없이 최근 로컬 기록의 토큰·시간으로 표시합니다. **측정 중지**로 현재 관측을 멈추고 **로컬 측정 시작**으로 다시 시작할 수 있습니다. 사용량 보기가 켜진 채 앱을 다시 시작하거나 Codex 연결로 전환하면 기본 자동 관측을 다시 시작합니다.

Codex는 **측정 출처**에서 **선택한 로컬 세션 파일** 또는 **새 CLI 세션의 trace**로 바꿀 수 있습니다. 새 trace 세션·Antigravity headless 방식은 **로컬 측정 시작 → 실행 명령 복사**의 명령을 새 터미널에서 실행해야 합니다. 이 방식은 생성된 명령으로 새로 시작한 세션만 수집하며 실행 중인 앱·IDE·기존 터미널에 자동 연결하지 않습니다. 사용자가 세션에서 실행하는 실제 요청에는 일반적인 한도·과금·도구 실행 조건이 적용됩니다.

| 제공자 | 표시하는 평균 | 시간과 토큰의 범위 |
| --- | --- | --- |
| Codex 로컬 세션, 턴 기록 | 진행 턴 평균 또는 완료 턴 평균 출력 `tok/s` | `token_usage_record`의 동일 턴 누적 `turn_token_usage.output_tokens` 중 마지막 관측값을 사용합니다. 진행 중에는 턴 시작부터 마지막 토큰 기록까지, 완료 후에는 같은 턴의 `task_complete.duration_ms`로 나눕니다. reasoning 토큰과 도구·승인·대기를 포함하는 턴 평균입니다. |
| Codex 로컬 세션, 메시지 기록 | 메시지 평균 출력 속도 `tok/s` | 완료된 `AgentMessage`의 `content_token_count`를 같은 항목의 `started_at_ms`부터 `completed_at_ms`까지 시간으로 나눕니다. reasoning 항목·도구 항목의 토큰이나 시간을 합치지 않습니다. |
| Codex | 응답 스트림 관측 평균 출력 `tok/s` | trace의 `receiving_stream` 시작부터 직접 연결된 `completed` 종료까지의 시간과 `gen_ai.usage.output_tokens`를 사용합니다. 출력에는 reasoning 토큰이 포함되고 스트림 대기·처리 시간이 포함됩니다. |
| Antigravity | step 평균 출력 `tok/s` | headless `stream-json`의 완료된 단일 `agent_response` step에서 `usage.output_tokens ÷ duration_seconds`를 사용합니다. 전체 실행의 누적 result 카운터를 사용하지 않습니다. |

이 값들은 모두 **순수 토큰 생성 속도나 여러 요청의 평균이 아닙니다**. 서로 관측 구간과 reasoning 포함 범위가 달라 제공자·출처 간 성능을 직접 비교하는 지표로 사용하지 마세요. 가장 최근 유효한 측정 하나를 표시하며 토큰·시간이 없거나 15분이 지나면 `—`로 표시합니다. 기준 시각은 Codex 진행 턴의 마지막 토큰 관측·완료 턴/메시지의 완료·trace 완료 시각, Antigravity bridge의 실시간 수신 시각입니다. 주간 한도 변화로 토큰 수를 추정하지 않습니다.

Codex 진행 중 값은 **마지막 출력 토큰 기록 시점까지**의 평균입니다. 출력 토큰 기록이 새로 들어올 때만 갱신하고 같은 턴의 누적 snapshot을 서로 더하지 않습니다. 도구·승인 대기 중이거나 토큰 기록이 없는 동안 벽시계만 늘려 속도를 다시 계산하지 않습니다. 완료 기록이 들어오면 완료 턴 평균으로 전환하며, 필요한 토큰·시간 기록이 없으면 값을 만들지 않습니다.

### Codex 최근 세션 자동 관측

선택한 Codex **계정 폴더**의 `sessions`를 관측합니다. 계정 폴더를 비우면 실행 환경의 `CODEX_HOME`, 없으면 기본 `~/.codex`를 사용합니다. 오늘을 포함한 최근 30일 날짜 경로의 세션 중 최근 15분 내 수정된 파일을 찾아 최신 최대 8개를 관측하고, 그중 최근 15분의 유효한 토큰·시간 기록 한 개를 표시합니다. 기록을 따라잡는 동안 읽는 중 상태와 관측할 수 없는 세션 수를 별도로 안내합니다.

폴더의 기록을 관측하는 것이며 현재 화면의 대화나 로그인 계정을 판별하지 않습니다. Codex 앱·CLI가 기록한 값이 있어야 하며 실행 중이어도 출력 토큰 기록이 없으면 `—`입니다. **30일 이전에 생성한 세션은 최근에 사용했더라도 자동 검색 대상이 아니므로 파일을 직접 선택**해야 합니다. 수동 선택도 표시 가능한 토큰·시간 기록은 최근 15분 이내여야 합니다.

### 선택한 Codex 로컬 세션 파일

Codex의 **측정 출처 → 선택한 로컬 세션 파일**을 고르고 **Codex 세션 JSONL 선택**으로 직접 파일을 지정한 뒤 **로컬 측정 시작**을 누릅니다. 파일의 `session_meta`와 같은 세션·턴의 토큰·시간 기록을 확인합니다. `token_usage_record`와 턴 기록은 `history_mode`가 `legacy`이거나 없어도 필요한 필드가 있으면 지원하며, 메시지별 기록은 해당 메시지의 토큰·시간이 있어야 합니다. 필드가 없는 기록에 대해 다른 턴·항목의 토큰이나 시간을 대입하지 않습니다.

선택한 파일의 최근 15분 내 토큰·시간 기록과 추가되는 기록을 관측합니다. 현재 대화나 계정을 자동으로 추정하지 않으며 세션 파일에 연결된 임시 측정 범위로만 구분합니다. 자동 관측과 수동 선택 모두 기존 Codex CLI·Desktop 계정의 신원을 증명하지 않습니다. 파일 경로 선택은 앱 재시작 후 자동 복원하지 않습니다.

본인 소유의 64 MiB 이하 일반 파일만 읽고 심볼릭 링크는 거절합니다. 파일당 한 번에 최대 1 MiB를 읽으며 파일이 교체·축소되면 기존 측정과 이어 붙이지 않습니다. 자동 관측과 수동 선택 모두 필요한 식별값·숫자·시간만 해석하고 대화 원문을 표시·저장하지 않으며 원본 JSONL도 수정하지 않습니다. 로컬 파일 관측에 새 모델 요청·telemetry 수신 키는 필요하지 않습니다.

### Codex trace 연결

Codex 명령은 해당 프로필의 `CODEX_HOME`과 OTLP trace 설정을 사용해 새 CLI 세션을 시작합니다. 명령은 이 실행의 기존 OTEL 로그·메트릭·trace 전송 설정을 대신하려 하므로 조직의 모니터링을 유지해야 하는 세션에는 사용하지 마세요. 회사 관리형 telemetry 설정이나 `otelHeadersHelper`가 우선하면 전송 대상·헤더가 바뀌거나 HappyLulu의 로컬 수신에 연결되지 않을 수 있습니다. 로컬로만 전송된다고 보장하지 않으며 실행 전에 관리 정책을 확인해야 합니다. 프롬프트·응답 등 내용 전송을 끄는 설정도 생성 명령에 포함합니다.

Codex trace에는 검증된 계정 신원이 없어 선택한 프로필의 임시 측정 연결로만 구분하며 서버 로그인 신원을 별도로 검증하지 않습니다.

### Antigravity headless 연결

생성된 명령은 터미널에서 요청을 입력받아 `agy -p` headless 세션을 `--output-format stream-json`으로 실행하고 그 출력을 HappyLulu의 측정 bridge에 전달합니다. 이 동작은 `/usage` 한도 조회와 달리 **실제 요청을 실행**합니다. 사용자 CLI의 MCP·훅·확장이 실행될 수 있으며 분리된 자식 프로세스는 남을 수 있습니다.

bridge는 CLI 표준 출력을 그대로 터미널로 전달하고, 유효한 완료 step에서 숫자 측정값만 로컬 수신기에 보냅니다. 계정 신원은 검증하지 않으며 이번 headless 연결의 임시 scope로만 구분합니다. `output_tokens`나 `duration_seconds`가 없는 step은 값을 만들지 않습니다. 보고된 step 시간에는 모델 대기·처리가 포함될 수 있습니다.

### 임시 키와 데이터 보관

생성 명령에는 이번 연결용 임시 키가 포함됩니다. 키가 명령·프로세스 인자나 환경·클립보드·터미널 이력에 노출될 수 있으므로 공유하지 마세요. **측정 중지**, 앱의 연결·연결 설정 변경, 플러그인 중지 시 수신을 닫고 키와 측정값을 폐기합니다. 기존 명령의 키는 무효가 되지만 명령 복사본·클립보드·터미널 이력을 자동으로 삭제하지는 않습니다.

측정값·중복 요청 식별값은 메모리에만 보관하며 HappyLulu가 프롬프트·응답 원문을 디스크에 저장하지 않습니다. Antigravity의 터미널에는 기존 CLI 출력이 그대로 보입니다. 측정을 중지해도 사용자가 실행한 CLI 세션 자체를 종료하지는 않습니다.

## 외관

macOS 26 이상에서 순정 리퀴드 글래스 테마를 선택하면 사용량 설정도 공통 설정 창의 시스템 색상·라이트/다크 모드·기본 컨트롤을 따릅니다. 사용량 행이 추가되면 메뉴 패널은 높이를 늘리고 메뉴바 항목 아래 위치를 유지합니다. 행을 누르면 사용량 플러그인 설정으로 이동하며, 더 보기 메뉴의 설정·종료 기능도 유지합니다.

플러그인의 SwiftUI 화면은 앱 전용 글래스 코드에 의존하지 않습니다. 창·탐색·재질은 호스트가 처리합니다. macOS 26 이상에서는 기존 테마에도 새 재질·메뉴 패널·제목 표시줄을 적용하며, 저장된 테마 색상과 아이콘은 유지합니다. 미지원 macOS에서는 기존 UI를 사용합니다.

## 구현 경계

- `AIUsagePlugin`: 제공자 어댑터, Codex RPC·로그인, 제공자별 한도 해석과 이력 분석, 선택한 로컬 세션 읽기, OTLP·bridge 수신과 토큰 속도 해석
- `AIUsageIntegration`: 플러그인 수명주기·설정·알림과 SwiftUI 상세 화면
- 공통 앱: 제공자가 등록한 메뉴 상태와 설정 화면만 사용하며 Codex 통신을 직접 수행하지 않음

`HAPPY_LULU_DISABLE_AI_USAGE=1`로 빌드하거나 두 플러그인 소스 디렉터리를 제거하면 기본 앱을 사용량 플러그인 없이 빌드할 수 있습니다. 출근 기록·캘린더 기능과 번들 식별자는 유지합니다. 이 구현은 macOS용이며 Windows 앱에는 연결하지 않습니다.

## 고정 개발 앱에서 사용

로컬 개발 후보는 `happylulu-dev`와 고정 번들 식별자 `local.chanyoung.HappyLulu.Dev.manual-leave.20261015`에서 AI 사용량 모듈만 선택적으로 실행할 수 있습니다. 처음에는 **사용량 보기**가 꺼져 있고 사용자가 켜야 시작합니다. 같은 Dev 프로필에서 이미 켠 설정은 재시작 후 유지하며 임의로 초기화하지 않습니다. 다른 개발·진단 식별자에는 이 실행 예외를 적용하지 않습니다.

AI 사용량을 켜도 캘린더·다우오피스·휴가 자동 인식·시스템 러너는 실행하지 않습니다. 자동 출근 감지·자동 업데이트·macOS 로그인 항목 변경과 기존 외부 계정 이관도 계속 차단합니다. 정식 `happylulu`의 출퇴근·플러그인·캘린더 동기화 저장소와 기존 Dev 기록 경로는 유지합니다. 앱의 저장소 분리와 외부 CLI 로그인 분리는 별개이므로 Codex의 기본 계정을 바꾸지 않으려면 위의 계정 폴더 분리 안내를 따라야 합니다.
