# Apple 설정과의 시각적 차이 분석

2026-11-14. 상태: **관찰과 개선 제안, 구현 전**. 이번 요청은 디자인 차이의 원인과 수정 방향을 정리하는 것이다. 기존 [현재 디자인 규칙](README.md)과 [메뉴 통합 결정](2026-11-14-sidebar-and-navigation.md)은 그대로 보존한다.

## 결론

현재 화면은 회색 사이드바, 흰 본문, 둥근 카드라는 큰 틀은 비슷하다. 차이는 **무엇을 강조하는지, 같은 종류의 설정을 어떻게 반복하는지**에서 생긴다. 큰 파란 심볼, 여러 단계의 굵은 글자, 행마다 다른 조작 위치, 긴 설명이 함께 시선을 끈다. 그래서 카드 밖은 여유가 있어도 카드 안은 빽빽하고, 화면마다 다른 규칙으로 만든 느낌이 난다.

특히 업데이트와 출근 기록을 기존 카드 형태로 일반·근무에 합치면서, 목적지는 통합했지만 내부의 제목·행·설명 규칙까지 통합하지 못했다. 업데이트에만 제목이 붙는 현상은 이 구성 차이에서 나온다. 색이나 투명도를 다시 바꾸기보다 글자 위계와 공통 행부터 정리하는 편이 효과가 크다.

## 비교 범위와 근거의 한계

- 체크아웃: `app/happylulu/issues-dev-20261109`, branch `mac/dev`, HEAD `947e59681b19102fed8d2a9ed339e5494c5dd910` 위의 기존 미커밋 작업 상태.
- 실제 앱: 고정 `happylulu-dev`의 일반·외관·근무를 읽기 전용으로 관찰했다. 비교한 시스템 설정 화면은 일반·언어 및 지역·디스플레이다. 관찰 후 Dev는 일반, 시스템 설정은 원래의 디스플레이 화면으로 돌려놓았다.
- 아래 HappyLulu 수치는 소스에서 확인한 값이다. Apple의 사이드바 경계 231.5pt는 해당 창의 접근성 정보이고, 아이콘 내부 크기·간격에 관한 설명은 화면 관찰이다. Apple의 공식 치수나 모든 macOS의 고정값으로 간주하지 않는다.
- 화면 공유·뷰어 배율이 다른 캡처의 픽셀을 직접 비교하지 않았다. 이전 캡처의 오른쪽 잘림만으로 앱의 레이아웃 결함을 확정하지 않는다.
- Apple HIG는 글자·심볼·조작의 위계를 판단하는 근거다. 이 문서의 제안 수치는 HappyLulu용 후보이며 아직 구현·사용자 수락으로 검증하지 않았다.
- 이번 분석에서는 앱 코드, 설치본, 설정값을 변경하지 않았다. 새 빌드·실행 테스트 결과를 주장하지 않는다.

### Apple을 잘못 단순화하면 안 되는 부분

Apple 설정도 모든 카드에 제목을 붙이지 않는다. 이번에 본 언어 및 지역에서는 `선호하는 언어`와 `응용 프로그램`은 카드 안에 제목이 있지만, 지역 옵션 묶음에는 별도 제목이 없다. 문제는 무조건 제목 유무를 통일하지 않았다는 데 있지 않다. **어떤 묶음에 제목이 필요한지와 같은 역할의 행을 어떻게 표시할지가 정해지지 않은 것**이 문제다.

Apple 일반 첫 화면에는 큰 소개 아이콘과 카드가 있지만, 사용자는 작은 상단 제목을 선택했다. 그 결정을 유지한 채 상세 설정 화면의 행·위계 규칙을 참고한다. 컬러 타일·큰 소개 카드·투명 배경을 다시 도입하는 제안은 아니다.

사이드바 폭은 Dev 230pt, 관찰한 Apple 창의 경계는 231.5pt로 이미 가깝다. 행의 세로 간격도 화면상 큰 차이가 없었다. 비교한 Apple 창 전체 폭은 약 740pt, Dev 최소 폭은 820pt라 본문이 더 넓어 보일 수 있지만, 이 740pt는 Apple 공식 최소 폭이 아니다. 최소 폭부터 줄이면 5개 아이콘·한영 문구·달력 배치가 달라지므로 후순위로 둔다.

## 공통 규칙 후보

수치 자체보다 역할과 적용 범위를 먼저 고정한다. 아래는 다음 구현을 위한 후보이며 현재 규칙을 덮어쓰지 않는다.

| 역할 | 현재 | 후보와 확인 기준 |
| --- | --- | --- |
| 화면 제목 | 15pt semibold, 높이 44pt | 유지. 스크롤과 분리하고 화면당 한 번 표시 |
| 구역 제목 | 13pt semibold | 13pt medium. 동급 묶음은 같은 위치와 들여쓰기 |
| 설정 항목명 | 일반 13pt medium, 다른 화면은 상속값 혼재 | 13pt regular. 글자가 길면 줄바꿈 허용 |
| 보조 설명 | 일반 11pt, 다른 화면 caption·상속값 혼재 | 11pt regular·secondary. 대비와 읽기 가능성 확인 |
| 사이드바 문양 | 15pt medium / 20pt 슬롯 | 13–14pt regular부터 비교 / 슬롯과 클릭 영역 유지 |
| 제목→카드 | 8pt | 10pt 후보. 구역 간격과 구분 |
| 카드→다음 구역 | 24pt | 우선 유지. 글자 경량화 후 실제 화면에서 재평가 |
| 설정 행 좌우 | 일반 14pt, GroupBox 내부 합계 13pt | 14pt로 공통화. 현재의 1pt 차이 자체는 핵심 원인이 아님 |
| 설정 행 위아래 | 일반 각 10pt, 다른 화면 개별 배치 | 각 10–12pt 범위에서 표준 조작 높이와 함께 확인. 고정 높이로 설명을 자르지 않음 |
| 항목명→설명 | 일반 4pt | 유지하고 다른 설정 행에도 같은 규칙 적용 |
| 테마 카드 내부 / 간격 | 6pt / 8pt | 8pt / 10pt 후보. 최소 창에서 8개 테마 표시 확인 |
| 모서리·기본 표면 | 카드 12pt, 회색 사이드바·흰 본문 | 유지. 테마 전환은 형태를 바꾸지 않음 |

Apple HIG는 macOS 기본 글자 크기를 13pt로 안내하고, 크기·굵기·색으로 정보 위계를 구분하도록 권한다. 따라서 본문 크기를 무조건 줄이기보다 regular와 강조의 역할을 정리하는 것이 우선이다. SF Symbols도 글자와 굵기를 맞출 수 있다. 위 후보의 구체적인 여백·심볼 크기는 HIG의 공식 수치가 아니다. [Apple Typography](https://developer.apple.com/design/human-interface-guidelines/typography)

Apple은 익숙한 사이드바 심볼과 의미가 분명한 색 사용을 권한다. 현재 파란색은 사용자가 선택한 제품 규칙으로 유지한다. 버튼은 시각적으로 강한 스타일을 주 동작에 제한하는 방향으로 맞춘다. [Apple Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars), [Apple Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)

## 일반 화면의 구성 예

다음은 정보 위계와 조작 정렬을 보여주는 개략도다. 픽셀 규격이나 완성 시안은 아니다.

```text
일반                              ← 작은 고정 화면 제목

사용 환경                         ← 구역 제목
┌────────────────────────────────────────────────┐
│ 언어                            시스템 언어  ▾ │
│ ────────────────────────────────────────────── │
│ 남은 시간 표시                        시/분  ▾ │
│ 예시: 1시간 29분                               │
│ ────────────────────────────────────────────── │
│ 메뉴바에 퇴근 예정 시각 표시             [스위치] │
│ ────────────────────────────────────────────── │
│ 로그인 시 자동 실행                     [스위치] │
└────────────────────────────────────────────────┘

업데이트                          ← 위와 같은 제목 규칙
┌────────────────────────────────────────────────┐
│ 현재 버전                              1.5.20 │
│ ────────────────────────────────────────────── │
│ 새 버전 자동 확인                       [스위치] │
│ 자동 다운로드 및 설치                   [스위치] │
│                              [지금 업데이트 확인] │
└────────────────────────────────────────────────┘
자동 설치 동작 요약 · 자세히…      ← 작고 일관된 보조 설명
```

실제 구현에서는 로그인 승인 상태, 업데이트 비활성 이유·오류, 자동 설치의 재시작·잠금 조건을 보존해야 한다. 위 개략도는 조건부 정보 전체를 열거하지 않는다. Dev의 비활성 업데이트 제어는 서비스 제한에 따른 상태이며 디자인 변경으로 해제할 대상이 아니다.

## 수정 순서와 구현 경계

1. **1차: 글자·아이콘·일반 화면 위계.** 사이드바 문양의 시각적 면적을 줄이고, 일반 항목명을 regular로 바꾼다. 일반/업데이트의 구역 제목과 오른쪽 조작 열을 맞춘다. 동일 화면 전후 비교로 효과를 판단한다.
2. **2차: 공통 설정 행과 설명.** 기존 일반 행을 기반으로 공통 행을 만들고 업데이트와 근무 시간에 적용한다. 구역·행·설명·동작 버튼의 역할을 분리하고 필요한 값만 `SettingsLayout`에 모은다. 개별 화면에 숫자를 추가해 맞추는 방식을 반복하지 않는다.
3. **3차: 외관·달력·플러그인 세부 조정.** 비선택 테마 카드의 경계, 달력 제목과 탐색 버튼의 강조를 조절한다. 플러그인 목록의 제품 소개 카드와 실제 설정 행은 목적이 다르므로 모두 동일한 작은 행으로 만들지 않는다.
4. **마지막: 창 폭과 미세 여백.** 앞선 변화 후 최소 폭·줄바꿈·정보량을 다시 판단한다. 검색·뒤로가기 기능 추가는 이번 느낌 차이를 해결하는 우선 작업이 아니다.

이 제안은 기존 기능의 시각 규칙 정리다. 새 기능 ID나 새 앱 bundle ID가 필요한 변경으로 보지 않는다. 설정 저장값, 업데이트 조건, 출근 계산, 플러그인 연결, 기존 접근성 식별자는 유지한다. 실제 규칙 반영 시에는 기존 사용자 요청에 따라 Astra 검수를 거쳐 현재 규칙과 명세를 함께 갱신한다. 이번 분석 문서에 이전 구현의 검수 결과를 재사용해 승인된 제안처럼 표시하지 않는다.

## 다음 구현의 수락 기준

- 일반과 업데이트에서 항목명·설명·조작이 같은 역할별 정렬선과 글자 규칙을 따른다. 페이지 제목과 구역 제목이 기능 없이 중복되지 않는다.
- 사이드바 아이콘이 글자보다 과도하게 강하지 않으면서 의미를 알아볼 수 있다. 작게 그려도 행의 클릭·키보드·접근성 영역은 줄이지 않는다.
- 최소 820pt 창에서 한국어·영어 긴 문구, 조건부 승인 버튼·오류, 8개 테마·5개 부엉이·달력이 잘리지 않는다. 고정 높이로 긴 설명을 숨기지 않는다.
- 테마 전환은 색만 바꾸고 형태·배치·여백은 유지한다. 선택은 테두리와 우상단 체크로 표시하고 위로 움직이지 않는다.
- 기본 밝은 화면, 어두운 화면, 활성·비활성 창 및 대비 설정에서 본문·보조 설명·선택 상태를 읽을 수 있다.
- 구현 검사는 기존 [설정 내비게이션 검사](../../docs/settings-navigation-check.md)를 사용한다. 실제 Dev의 육안 비교·키보드·VoiceOver는 자동 렌더 검사와 별도로 기록한다. 합성 데이터와 실제 Dev 저장소는 분리한다.
- 분석의 완료와 디자인 적용의 완료를 구분한다. 이 문서에는 제안 구현, 새 빌드, 사용자 수락 결과가 없다.
